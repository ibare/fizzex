## 1. 왜 곡선이 아니라 씬인가

프로젝트 전체가 이 한 문단에서 나왔다.

> 좌표 평면에 곡선을 그리는 것만으로는 학습자에게 가치를 주기 어렵다.
> $y = x^2$의 포물선을 보여주고 슬라이더를 붙여도
> 학생의 반응은 "예쁘네. 그래서 뭐?"이다.
> 하지만 같은 수식이 **현실의 모형**과 연결되면 완전히 다르다.
> 케플러 제3법칙에서 궤도 반지름을 바꾸면 ISS가 느려지고 달이 빨라지는 것,
> 원의 넓이에서 반지름을 바꾸면 피자 크기가 4배로 달라지는 것 —
> 이것은 곡선이 아니라 현실이고, 이해가 일어나는 지점이다.
> — `FW:15-22`

> 이런 현실 모형은 범용 그래프로는 만들 수 없다. 위성 궤도, 피자 크기 비교,
> 포물선 공 궤적, 파동 물결은 각각 고유한 시각적 경험이며 개별 구현이 필요하다.
> — `FW:24-26`

### Desmos 와 무엇이 다른가

> Desmos가 수식을 그래프로 그리는 도구라면, Fizzex는 **수식이 현실에서 어떻게
> 나타나는가**를 보여주는 도구다. — `PYT:11`

차이가 가장 선명한 예:

> Desmos에서 이 수식을 치면 P, r, t를 -10~10 슬라이더로 조작하게 되는데,
> r = -3이나 P = -8 같은 경제적으로 무의미한 값이 된다.
> Fizzex는 P(원금)는 만 원 단위, r(이율)은 %로, t(기간)는 년으로 범위가 묶여 있다.
> — `V-COMP:8-11`

**파라미터의 의미 있는 범위·단위·스케일을 데이터가 소유한다**는 것이 차별점의
핵심이다. 지금은 카탈로그의 `parameterConfig`(범위·단위·`scale: log`)와
spec 의 `scenes[].params` 가 그 역할을 한다.

### 수식별 "학습자가 얻어야 할 것"

새 씬을 설계하거나 수식을 추가할 때의 기준선.

| 수식 | 체감시켜야 하는 것 | 출처 |
|---|---|---|
| 피타고라스 | 같은 직각삼각형이 맥락(사다리·TV·지름길)에 따라 다른 의미를 갖는다 | `PYT:9` |
| 사인파 | "이 다른 현상들이 전부 같은 수식" — 소리·전기·조수·진자가 구조는 같고 맥락만 다르다 | `V-SINE:8-9` |
| 이차함수 | a→열림·폭, b→좌우, c→상하. 추상 계수가 다리 아치·분수·농구 궤적으로 나타난다 | `V-QUAD:8-10` |
| 자유낙하 | g가 명확한 상수 → 상수 편집 금지가 자연스럽게 드러나는 첫 사례. g를 바꾸면 "어떤 행성에서도 일어나지 않는 낙하" | `V-FALL:8-10` |
| 복리 | "시간이 돈을 번다" | `V-COMP:13` |
| 지수 감소 | "절반이 되는 데 걸리는 시간은 언제나 같다." 복리와 거울상 | `V-DECAY:8-10` |

### 수식 1 : 시각화 N

> 케플러 제3법칙만 해도: 2D 궤도 / 3D 궤도 / T² vs a³ 그래프 / 태양계 스케일 비교.
> 원의 넓이도: 2D 원 + 면적 / 격자 채우기 / 피자 비교.
> 각 시각화는 같은 파라미터를 받고 같은 프로토콜로 통신하지만 **보여주는 관점이
> 다르다.** — `K3D:71-84`

아직 만들지 않은 관점 아이디어: **T² vs a³ 그래프**, **태양계 스케일 비교**,
**원 넓이의 격자 채우기 / 피자 비교**.

시각화는 **선택적 기능**이다. 형식에 매칭되지 않는 수식은 탐색 모드만 뜬다 (`FW:714-716`).

## 2. 불변 원칙 셋

`K3D:3-65` 에서 정식화됐고 JSON spec 런타임에서도 그대로 참이다.

### 원칙 1 — 데이터 원천은 수식이다

> Visualizer는 **자체 계산을 하지 않는다.** 주기, 속도, 고도, 면적 등 모든 파생값은
> 프레임워크가 수식 평가로 계산하여 전달한다.
>
> 이유: 사용자가 수식의 상수(예: $4\pi^2$를 $6\pi^2$로) 편집하면 수식의 평가 결과가
> 물리적 상수값과 달라진다. Visualizer가 자체 계산하면 수식 영역의 값과 시각이
> 어긋난다. 원천을 하나로 고정하면 이 불일치가 원천 차단된다. — `K3D:8-18`

| | |
|---|---|
| **금지** | viz 내부의 `calcPeriod`/`calcVelocity` 류 / $G$·$M$ 같은 상수를 아는 것 / 수식 재평가 |
| **허용** | 스케일 변환(km→화면 좌표) / 애니메이션 보간 / 카메라·뷰 변환 |

수식별 금지 표현 — 그대로 체크리스트로 쓸 수 있다:

| 수식 | 쓰면 안 되는 것 |
|---|---|
| 피타고라스 | `Math.sqrt(a*a+b*b)` |
| 이차함수 | `a*x*x + b*x + c`, 꼭짓점 `-b/(2*a)` |
| 자유낙하 | `0.5 * g * t * t` |
| 복리 | `P * Math.pow(1 + r, t)` |
| 지수 감소 | `N0 * Math.exp(-k * t)`, 반감기 `ln(2)/k` |

**"display 영역"이라 허용되는 경계선** — 판정 기준이 잘 서 있는 사례들:

- 탄소-14 입자 그리드의 활성 개수 `round(100 * N/N₀)` — "수식 평가가 아닌 시각화 매핑" (`V-DECAY:82`)
- 배터리 잔량 → 색 변환 (`V-DECAY:83`)
- 금액 포맷(천 단위 콤마, 만원 단위) — "받은 값을 포맷만 하는 건 허용" (`V-COMP:79`)
- 장식적 애니메이션(음파 리플, 잔물결)이 시간 t를 직접 쓰는 것 — "수식 파이프라인과 무관" (`V-SINE:87`)

### 원칙 2 — 상수는 편집 금지

> $G$, $M$, $\pi$ 같은 상수는 `elementMeanings` 에서 `kind: 'constant'` 로 표시되고
> 사용자는 값만 볼 수 있다. — `K3D:29-32`

파생: g는 씬 전환으로만 바뀐다 (`V-FALL:83`). e·k는 상수, N₀는 `kind: 'input'` 이라
사용자가 바꿀 수 있다 — "커피 2잔이면 190mg" (`V-DECAY:79-80`).

### 원칙 3 — baseline 대비 current 이중 표시

편집 가능한 값을 둘로 나눈다 (`K3D:34-53`):

- **바뀌어도 수식이 유효한 값** — 궤도 반지름 a를 10,000km로. 여전히 올바른 궤도.
- **바뀌면 수식이 변질되는 값** — $4\pi^2$의 4를 6으로. 물리 공식에 어긋남.

> 두 상태를 **동시에 시각화**한다. baseline 기준 "정상 상태", current 기준 "사용자
> 상태", 차이가 있을 때 대비가 시각적으로 드러나게. 이를 통해 사용자는 자유롭게
> 편집하면서도 "이 값이 왜 이 값이어야 하는지" 인지할 수 있다. — `K3D:55-65`

> ⚠️ **원칙 3의 시각적 적용은 [`lessons.md`](./lessons.md) L1 이 우선한다.**
> `K3D:780-786` 은 궤도 링까지 빨갛게 칠하라고 했지만 실전에서 뒤집혔다 —
> 사용자 피드백: "궤도는 공통 요소인데 빨간색으로 변하니까 매우 혼란스럽다."
> **차별화 대상은 derived 값에 의존하는 요소뿐이다.** input 으로만 결정되는
> 요소(위치·크기)를 색으로 구분하면 노이즈가 된다.

> ⚠️ **원칙 3은 현재 런타임에서 동작하지 않는다.** `baseline`·`isStandard` 는
> Expression 컨텍스트에 주입되지 않는다. 자세한 것은
> [`visualizer-authoring.md` 의 구현 상태](./visualizer-authoring.md#구현-상태)를 볼 것.

### 어휘 대응표

| 옛 어휘 | 현재 |
|---|---|
| `params.correct` / `derived.correct` | `baseline.params.*` / `baseline.formulas.*` (미구현) |
| `params.current` / `derived.current` | `params.*` (bare 이름으로도 노출) |
| "correct 와 current 가 같은가" | `isStandard` (미구현) |
| preset (프리셋), anchor (앵커) | **Scene** — `scenes[]`, `scene.id`, `scene.style` |
| displayParameter | **displayOptions** — 호스트 opt-in, baseline 비교 대상 아님 |
| 카탈로그가 viz 를 직접 소유 | `catalog → form → viz` (형식이 소유) |

## 3. 장면 디자인 규칙

### 설명을 시각화에 녹이는 다섯 원칙

> 텍스트 패널은 Fizzex Visualizer 공간에 들어갈 자리가 없다. 그 정보를 **공간 자체**로
> 전달한다:
>
> 1. **장면의 형태가 맥락이다** — 집 벽·창문 = 건물, TV 스탠드 = 가전, 잔디 = 공원.
>    글자 없이도 인식되는 실루엣을 우선.
> 2. **앵커는 공간 좌표로** — "2층 창문 ~5m"는 창문을 Y=5m 위치에 그리는 것으로 대체.
>    학습자는 무의식적으로 "창문 높이쯤"이라는 감각을 얻는다.
> 3. **제약은 상태 배지로** — 안전각, 절약률 등은 작은 색상 배지. 좌상단. 약 30자 제한.
> 4. **수치는 측정선으로** — 브래킷 + 라벨. 건축 도면 스타일. 텍스트 블록 금지.
> 5. **행동은 아이콘으로** — 발자국, 움직임은 단순 마크. 애니메이션 불필요.
>
> — `PYT:201-209`

### 절대 금지

> - 시각화 밖 별도 텍스트 영역 배치
> - 프리셋별 설명 팝업/툴팁
> - 한 줄 30자 초과 레이블
> - 화면 하단 또는 상단에 긴 문장 캡션
>
> — `PYT:211-215`

### 요소 상한

> 각 씬에 등장하는 요소는 다음 수를 넘지 않게 유지:
> 주 오브젝트 1개 · 보조 오브젝트 최대 3개 · 배지 1개 · 측정선 3개 ·
> 텍스트는 값 라벨과 배지 텍스트만.
>
> **복잡도가 증가하면 "장면이 곧 설명"이라는 원칙이 붕괴한다.** — `PYT:217-225`

텍스처 밀도 상한: **잔디 25개, 벽돌 8줄, 지면 해칭 20개.** 이상이면 노이즈 (`PYT:253`).
사다리 가로대: `max(3, floor(c * 3))` (`PYT:259`).

### 레이아웃

상단 42% 추상 시각화 : 하단 58% 현실 장면, 경계는 연한 점선, 좁은 창(~500×500) 기준
(`PYT:74-98`).

> 이중 구도 자체는 viz 별 선택이다. `GHA:10` 이 "이중 구도 폐기, 각 viz 는 자기 뷰만"으로
> 결정했으나, 실제로는 `sine-wave-2d`·`compound-interest-2d`·`exponential-decay-2d` 가
> 여전히 `frame.height * 0.42` 분할을 쓴다. **42/58 은 "이중 구도를 쓸 때의 표준 비율"** 로
> 살아 있다.

### 씬 전환 연출

페이드아웃 ~200ms → 페이드인 ~300ms. 상단 추상은 전환 없이 값·색상만 보간 (`PYT:229-235`).

> **동작 먼저, 장면 완성도 다음, 전환 애니메이션 마지막.** — `PYT:316`

### 씬별 색상 (피타고라스 예)

추상의 크기·구성은 동일하고 색만 다르다 (`PYT:110-114`).

| 씬 | 색 |
|---|---|
| 자유탐구 | `#0F172A` (수학적 중립) |
| 사다리 | `#DC4C2C` |
| TV | `#7C3AED` |
| 지름길 | `#0E7490` |

### 파생값 노출 정책

> 파생값이 별도 섹션으로 노출되지 않아야 한다. 그러나 계산된 각도·안전성·절약률 등을
> **장면 요소의 일부로** 표시하는 것은 허용. (사다리 안전 배지, 지름길 절약률 배지)
> — `PYT:36`

## 4. 안티패턴

`PYT:239-259` 원문. LLM 이 특히 잘 빠지는 함정을 조준해 쓰였다.

> ❌ **viz 내부에서 c 계산** — 수식 평가 결과를 받을 것. `Math.sqrt(a*a+b*b)` 금지.
> ❌ **각 씬이 자체 전체 레이아웃 렌더** — 상단 추상은 공통. 씬은 하단 장면만 교체.
> ❌ **DOM 오버레이로 설명 텍스트** — 배지 포함, 캔버스 안에서 그릴 것.
> ❌ **긴 설명 문장** — 30자 이내. "벽에 기대 세운 사다리는 바닥과의 거리와…" 같은 서술문 금지.
> ❌ **씬 버튼을 viz 내부에 그림** — 씬 칩은 프레임워크 chrome 이 담당.
> ❌ **격자·해칭·텍스처 과다** — 잔디 25, 벽돌 8줄, 해칭 20이 상한.
> ❌ **baseline 상태 무시** — 인터페이스에 있으니 수신할 것.
> ❌ **사다리 가로대를 200개씩** — `max(3, floor(c*3))` 정도.

다른 문서에서:

- ❌ **미래 대비 확장** — "Host 인터페이스를 '미래에 필요할 것 같아서' 확장하지 마라. 실제로 쓰는 것만 추출." (`GH:129`)
- ❌ **이벤트 시스템 과설계** — 현재 쓰는 패턴만 (`GH:135`)
- ❌ **잔물결과 본질 운동의 혼동** — "조수의 잔물결과 수면의 y₀ 기반 높이 변화는 독립." (`V-SINE:88`)
- ❌ **랜덤 소멸** — 탄소-14 입자는 "랜덤이 아니라 정해진 순서(시드 고정, 재현 가능)" (`V-DECAY:36`)

| 프레임 콜백 `{dt, now}` — 필요 없으면 무시 | 수식 값 해석 |
| 테마 팔레트 (light/dark) | 씬 로직 · 장면 전환 |
| 좌표계(뷰포트) 라이브러리 | 자체 이벤트 리스너와 그 정리 책임 |
| 3D: Three.js 라이프사이클 | 3D Mesh/Geometry/Material **생성** (dispose 훅만) |

호스트에 올리지 않기로 한 것: **ResizeObserver**(외부가 `resize(w,h)` 호출, `GHA:86-88`),
**자동 재생 로직**(`GHA:123`).

### 뒤집힌 원칙 — 반드시 함께 읽을 것

> 핵심 원칙: **Visualizer 작성자가 `ctx` 에 직접 접근할 수 있어야 한다.** Host 는 편의를
> 주되 가두지 않는다. `ctx` 를 감추는 래퍼가 아니라 `ctx` 위에 얹는 유틸리티. — `GH:99`

**이 원칙은 JSON spec 전환으로 명시적으로 뒤집혔다.** 지금은 `ctx` 도 `THREE` 객체도
노출되지 않는다. 새 시각 표현이 필요하면 spec 에 탈출구를 뚫는 것이 아니라
**프리미티브를 확장**한다 (C9:40-41). "가두지 않는다"의 정신은
**"프리미티브 어휘를 충분히 풍부하게 유지한다"** 로 계승됐다고 읽는 것이 맞다.

같은 이유로 무효: `mount()/update()/resize()/unmount()` 4-메서드 라이프사이클을
작성자가 구현한다는 서술 전체 (C9 MUST NOT 이 정면으로 금지).

또 하나 뒤집힌 것: `GHA:112-114` 는 "기본 도형 헬퍼는 Host 미제공, 공통 헬퍼 후보 부족"
이라 판정했으나, 현재는 정반대로 **호스트가 프리미티브를 제공하고 viz 는 조립만** 한다.

### 좌표계 3종 — 실측 기반

2D viz 7개 전수 조사에서 좌표 변환 패턴이 정확히 셋으로 수렴했다 (`GHA:100-110`).
새 viewport 종류를 추가할지 판단할 때 인용할 수 있는 근거다.

| 종류 | 당시 사용 | 형태 |
|---|---|---|
| `TimeValueViewport` | compound, exponential, freefall, quadratic, sine-wave | `(xMin, xMax, yMin, yMax, yUp, padding)` + `toScreen(wx, wy)` |
| `BBoxViewport` | pythagorean | `(bbox, padding)` → 중심 정렬 + 자동 스케일 |
| `PolarViewport` | kepler-orbit-2d | `(cx, cy, scale)` + `toScreen(radius, angle)` |

3D 는 Three.js 카메라가 이 역할을 하므로 별도 뷰포트가 없다. `yUp` 은 기본 true(수학
좌표계), false 면 y-down 화면 좌표계 (`GHA:237`).

### 테마 팔레트 5색 — 미완의 좋은 아이디어

"표준 5색 + 도메인 강조색"이라는 분리는 아직 구현되지 않았다.

### Three.js 격리

- `Graphics3D` 만 `import * as THREE`. 2D 경로는 절대 import 금지 (`GHA:172-177`)
- 번들: 전체 ~600KB → tree-shaking 시 ~150KB. 3D 를 선택한 사용자만 로드하므로 코어에 영향 없음 (`K3D:872-875`)
- WebGL 미지원: 3D 옵션을 숨기거나 로드 시 체크 후 폴백 (`K3D:877-879`)
- 모바일: 저사양 감지 시 별 수를 줄이거나 안티앨리어싱 해제, 또는 3D 옵션 숨김 (`K3D:888-890`)
- 함정: **Three.js r128 에는 `CapsuleGeometry` 가 없다.** `SphereGeometry`·`CylinderGeometry` 사용 (`K3D:885-886`)
- 확정 설정값: `WebGLRenderer(antialias, alpha=false, preserveDrawingBuffer)`, `PerspectiveCamera(fov=50, near=0.05, far=2000)` (`GHA:158-160`)

## 6. 수식별 씬 설계 자료

### 6.1 피타고라스 $a^2+b^2=c^2$

공통 추상(상단) — 직각삼각형 + 직각 인디케이터, 세 변 위의 정사각형, 각 정사각형
내부에 넓이값(`a² = 1.44`), 변 옆에 길이 라벨, bounding box 기준 자동 fit (`PYT:100-108`).

| 씬 | 기본값 | 범위 | 현재 |
|---|---|---|---|
| 자유탐구 | a=3, b=4 | — | ✅ |
| 사다리 | a=1.2m, b=4.8m | a∈[0.3,3.0], b∈[2.0,6.0] | ✅ |
| TV | a=1.218m, b=0.685m (55인치 16:9) | a∈[0.2,2.5], b∈[0.1,1.5] | ✅ |
| 지름길 | a=80m, b=60m | a,b∈[20,200] | ✅ |

- **자유탐구** — 격자 배경이 "순수 기하학" 맥락을 전달. a·b가 정수면 눈금과 맞아 "이산적 자연수 관계" 암시. 현실 장식 없음 (`PYT:118-129`)
- **사다리** — 집 벽(벽돌) + 창문 + 바닥 해칭 + 사다리(레일 2 + 가로대) + 좌상단 안전 배지. **창문 Y ≈ 5m 가 "2층 높이" 앵커를 공간으로 표현.** 가로대 수 ∝ c. 안전 임계: **70–80° 안전 / 60–70°·80–85° 주의 / 그 외 위험** (`PYT:133-155`)
- **TV** — 본체(베젤+화면+스탠드) + 대각선 점선 + 중앙 인치 숫자 + cm 측정선. 이 씬만 cm 표기. **16:9 는 기본값일 뿐 제약이 아니다** — 슬라이더로 벗어나도 허용 (`PYT:158-175`)
- **지름길** — 위에서 본 사각 영역 + L자 점선 + 대각선 실선 + **발자국 마커**("사람들이 실제로 가로지른다"는 행동적 함의) + 절약률 배지. 배지 형식: `돌아가면 140m · 가로지르면 100m · 29% 절약` (`PYT:179-197`)

미반영: 사다리의 **창문·벽돌 텍스처**, 지름길의 **발자국 마커**, 자유탐구의 정수 격자 스냅 힌트.

### 6.2 사인파 $y = A\sin(\omega t + \phi)$

추상 — 왼쪽에 반지름 A 원 위를 각속도 ω로 도는 점, 오른쪽에 그 y좌표가 시간축으로
펼쳐진 파형, **둘을 점선으로 연결 → "사인은 회전의 그림자"** (`V-SINE:13-17`).

| 씬 | 실제 주파수 | 권장 timeScale | 캡션(20자) | 현재 |
|---|---|---|---|---|
| 라(A4) 음 | 440 Hz | 0.005 | `스피커 진동판 → 공기 → 소리` | 리플 5개 ✅ / 캡션·realHz ❌ |
| 가정용 교류 | 60 Hz | 0.02 | `전압계 바늘 → 가전제품 전원` | 게이지+바늘 ✅ / `±311 V` 박스 ❌ |
| 조수 | ~12.4시간 주기 | 20000 | `바다 수위 → 배가 오르내림` | 수면+잔물결 ✅ / 배·등대·수위 눈금 ❌ |
| 진자 | 0.5 Hz | 1 (실시간) | `추의 각도 → 흔들림` | 줄+추 ✅ / 각도 인디케이터·궤적 호 ❌ |

상세 수치 (`V-SINE:41-74`): 스피커 리플은 **원호 5개**, 멀어질수록 fade, y₀ 클수록 강하게.
전압계 **바늘 각도 = π + (0.5 + y₀×0.5)π**, 디지털 `±311 V`(220Vrms 의 peak).
조수 수면은 **60 segment 와이어 + 하단 fill**, 등대는 3줄 적백 띠 고정.
진자 **각도 = y₀ × π/4 (최대 45°)**, 궤적은 줄 길이 반지름의 호 점선.

구동 규칙: **모든 장면은 y₀ 하나에서 구동된다.** 각 장면은 y₀ → 시각 매핑만 담당 (`V-SINE:85`).

> **`timeScale` 2모드 설계 — 이름만 채택되고 내용은 미구현.** 손실 위험이 가장 큰 자료다.
>
> - **스타일화**: ω를 그대로 사용. 교육용 기본 모드.
> - **실제 시간 스케일**: 씬의 `realHz` 반영. `effOmega = 2π × realHz × timeScale`.
>   ω 슬라이더 잠김, 시간축 라벨이 실제 단위(ms·시간)로, timeScale 은 로그 슬라이더 (10⁻⁵~10⁵).
>
> — `V-SINE:20-37`, `:86`

### 6.3 이차함수 $y = ax^2+bx+c$

추상 — 포물선 + 꼭짓점·대칭축·x절편, baseline(반투명) vs current(실선), 꼭짓점 좌표 라벨,
실근이면 x축 교점 마커 (`V-QUAD:14-21`).

| 씬 | 문서 기본값 | 현재 spec | 배지 |
|---|---|---|---|
| 자유 탐구 | a=1, b=0, c=0 | 동일 ✅ | — |
| 다리 아치 | a=-0.01, c=20 | a=-0.05, c=5 (스케일 조정) | `높이 {}m · 경간 {}m` ✅ |
| 농구 자유투 | a<0, c≈2 | ✅ | `최고점 · 비거리` ✅ |
| 분수 | a<0, c>0 | ✅ | `최대 높이` ✅ |

- 다리 — 수면 + 아치 + **교각 2개**(x절편 위치) + 반사. **판별식<0 이면 교각 없이 아치만** (`V-QUAD:34-41, 71`)
- 농구 — 코트 측면도 + 선수 실루엣 + 골대. 두 번째 x절편 = 착지 지점 (`V-QUAD:43-49`)
- 분수 — 분수대 + 물줄기 + 수반. 여러 물줄기를 다른 a로 겹치면 분수 느낌(장식) (`V-QUAD:51-57`)

일관성 규칙:

> a의 부호가 장면의 방향을 결정한다는 일관성: 자유탐구에서만 a > 0(위로 열림),
> 나머지는 모두 a < 0(아래로 열림 = 현실 궤적). — `V-QUAD:64`

### 6.4 자유낙하 $h = \tfrac12 g t^2$

추상 — 세로축 h, 가로축 t, **y축은 하향**(위에서 아래로 떨어지므로). baseline vs current
이중 곡선 (`V-FALL:14-19`).

| 씬 | g | 배지 |
|---|---|---|
| 지구 | 9.807 | `지구 · g = 9.8 m/s²` |
| 달 | 1.625 | `달 · g = 1.6 m/s²` |
| 화성 | 3.721 | `화성 · g = 3.7 m/s²` |
| 목성 | 24.79 | `목성 · g = 24.8 m/s²` |

지구 씬 이정표 — **10m(3층), 50m(아파트), 274m(63빌딩), 555m(롯데월드타워)**. 현재 spec 에
반영됨. 달은 크레이터 + 우주복 실루엣, 화성은 붉은 지형 + 로버, 목성은 가스 대기 그라데이션.

애니메이션: **공이 바닥에 닿으면 바운스 없이 정지.** `playbackSpeed` displayOption
후보(0.25×~2×)는 미반영 (`V-FALL:52-62`).

프레임워크 흐름의 모범 서술: "씬 전환으로 g가 바뀌면 프레임워크가 수식을 재평가하고
새 h를 전달. Visualizer 는 장면만 교체." (`V-FALL:85`)

### 6.5 복리 $A = P(1+r)^t$

추상 — 지수 곡선 + baseline/current 두 곡선 + **원금 P 를 수평 기준선(점선)으로** (`V-COMP:17-23`).

| 씬 | 문서값 | 현재 | 배지 |
|---|---|---|---|
| 예금 | P=1,000만, r=3% | ✅ | `3% · 24년 후 2배` ✅ |
| 주식 장기투자 | P=1,000만, r=7% | ✅ | `7% · 10년 후 2배` ✅ |
| 고금리 적금 | P=100만, r=5% | ✅ | `5% · 14년 후 2배` ✅ |
| 인플레이션 | P=1,000만, r=3% | ✅ | `3% 인플레 · 24년 후 절반` |

예금은 동전 스택(높이 ∝ A/P) + 72의 법칙 `×2` 마커. 주식은 5년 단위 막대 + 이정표
**10년(×2)·20년(×4)·30년(×8)** (×4·×8 미반영). 적금은 저금통 크기 ∝ A/P.

**인플레이션 씬의 설계 주의** (`V-COMP:47-53, 78`):

> 수식 구조는 동일하지만 의미가 반대다. "1,000만 원의 구매력이 30년 후 얼마로
> 줄어드는가". **수식 자체를 바꾸는 게 아니라** 카탈로그 `derivedValues` 에 "실질
> 구매력 = P²/A" 같은 파생값을 정의하고 viz 는 그것을 시각화한다.

배치 규칙: 금융 비교에서는 겹치기보다 **나란히** 배치 (`V-COMP:58-59`).
금액은 만원 단위(`1,967만원`). r은 수식에선 소수(0.03), UI 에선 %(3%) — 변환은
카탈로그의 단위 정보가 담당 (`V-COMP:66, 77`).

### 6.6 지수 감소 $N = N_0 e^{-kt}$

추상 — 세로축은 **N/N₀ 정규화 비율(0~1)**, 반감기 마커 (`V-DECAY:14-19`).

**반감기 시각적 강조가 이 viz 의 핵심 학습 목표** (`V-DECAY:60-67`):

> - N/N₀ = 0.5 수평 점선에서 t축까지 수직 점선 → "이 시간이 반감기"
> - 같은 패턴을 0.25, 0.125 에서도 반복 → "반감기가 일정하다" 시각적 증명
> - 각 수평선에서 수직선까지의 t 간격이 동일함을 강조

| 씬 | N₀ / 반감기 | 구성 | 미반영 |
|---|---|---|---|
| 카페인 | 95mg / 5시간 | 커피 컵 + 수위 | 수면 시각 앵커("아침 9시 커피 → 밤 9시에도 ¼") |
| 탄소-14 | 정규화 / 5,730년 | **10×10 입자 그리드**, 활성 = round(100×N/N₀), 시드 고정 순서 | timeScale (1년~50,000년) |
| 약물 | 400mg / 2시간 | 인체 실루엣 + 혈관, 채도 ∝ N/N₀ | **복용 간격 6시간(⅛) 마커** |
| 배터리 | 100% / ~3시간 | 배터리 fill, **100~50% 초록 / 50~20% 노랑 / 20%~ 빨강** | 충전 필요(10%) 마커 |

교육적 정직성: "실제 배터리 방전은 순수 지수 감소가 아님. 교육적 근사." (`V-DECAY:53`) —
현재 spec 에 캡션으로 살아 있다.

### 6.7 케플러 제3법칙 — 3D 씬

구성 (`K3D:775-805`): 파란 구체(MeshPhongMaterial, 텍스처 없이) + 반투명 대기
글로우(BackSide) + 느린 자전(시각 효과, 물리 아님). 궤도는 baseline 파란 링 /
current 빨간 계열. 씬 궤도(ISS·GPS·GEO)는 반투명 링으로 상시. **달 궤도는 스케일
차이가 커서 3D 에서 생략.** 별 배경, DirectionalLight 로 낮/밤 경계 + 약한 AmbientLight.

**로그 스케일 배치 공식** — 현재 spec 은 선형 `a/6371` 을 쓴다. 미채택 아이디어:

```
logMin = ln(6371), logMax = ln(50000)
sceneR = 1.2 + (ln(max(km, 6371)) - logMin) / (logMax - logMin) * 4
```

목적: "ISS~GEO 범위가 시각적으로 구분되게" (`K3D:547-554`).

**2D vs 3D 관점 비교** — 관점을 추가할 때의 템플릿 (`K3D:809-818`):

| | 2D | 3D |
|---|---|---|
| 관점 | 위에서 내려다봄 | 자유 회전 |
| 지구 | 원 + 그라디언트 | 구체 + 대기 + 자전 |
| 카메라 | 고정 | 드래그 회전 + 줌 |
| 달 궤도 | 표시 (로그 스케일) | 생략 |
| 고도 | 텍스트 라벨 | 표면~궤도 거리로 시각적 |
| 성능 | 가벼움 | 무거움 (WebGL) |

관점 전환 시 **파라미터 값은 유지**된다 — 같은 궤도 반지름에서 관점만 바뀐다 (`K3D:840, 881-883`).

## 7. 검수 체크리스트

피타고라스용 원본 (`PYT:298-312`). **"검증 가능한 형태로 쓴다"는 형식 자체가 자산**이다.

- [ ] 4개 씬 전환이 모두 동작
- [ ] a, b 값 변경 시 추상·현실 모두 즉시 반응
- [ ] 추상에서 `a² + b² = c²` 넓이 관계가 시각적으로 확인됨
- [ ] 사다리 각도에 따라 안전 배지 색이 변함
- [ ] TV 인치 표기가 `c * 39.37` (소수점 1자리)
- [ ] 지름길 절약률이 `(a+b-c)/(a+b) * 100` 에 정확히 일치
- [ ] Retina 에서 선명 (DPR 반영)
- [ ] 리사이즈 시 비율 유지 + 재렌더
- [ ] 30자 초과 텍스트 없음
- [ ] viz 내부에서 `Math.sqrt` 호출 없음
- [ ] baseline 파라미터 수신 구조 존재 (사용은 선택)

**새 viz 용 템플릿**: ① 모든 씬 전환 동작 ② 파라미터 즉시 반응 ③ 수식의 핵심 관계가
시각적으로 확인됨 ④ 배지 임계값 전환이 눈에 보임 ⑤ **도메인 단위 변환 공식의 수치
일치**(인치 39.37, 절약률 공식 등) ⑥ DPR·리사이즈 ⑦ 30자 초과 없음 ⑧ **spec 내 수식
재계산 표현 없음** ⑨ baseline 수신 구조.

## 8. 그 밖

### 성능·접근성 예산

- **성능**: "슬라이더 드래그 중 초당 60회 호출될 수 있다. update 와 파생값 계산이 **16ms 안에** 완료되어야 한다." (`FW:718-720`)
- **접근성**: "슬라이더는 키보드로 조작 가능해야 한다. 시각적 정보는 파생값 카드로도 접근 가능하므로 viz 가 순수 시각적이어도 정보 접근성은 유지된다." (`FW:725-727`)
- rAF 는 unmount 에서 반드시 cancel, 파괴 상태에서 콜백 호출 금지 (`FW:707-709`)

### id 명명과 "씬이냐 별도 viz 냐"

규칙은 `<수식키>-<관점키>-<차원>` 플랫 구조, 계층 디렉터리 금지 (`GHA:328-341`).

실제로는 **피타고라스·이차함수만 관점별로 쪼개졌고**, 사인파·복리·지수감소·자유낙하·
케플러는 **단일 viz + `scenes[]`** 로 남았다. "32개 완전 분리"안은 부분 채택되고 Scene 이
정식 어휘로 부활했다. 새 viz 에서 **"관점을 별도 viz 로 뗄 것인가, scene 으로 둘 것인가"**
는 여전히 판단 사항이다.

판단을 쉽게 만드는 작성 요령 (`GHA:368-372`): **씬을 상대 좌표 rect 기준으로 그려두면
분리·합치기 비용이 낮다.**

### "기본 상태 = 그 씬의 프리셋"

> 프리셋의 `values` 는 각 viz 의 `parameters[].default` 로 이관된다
> (프리셋 진입 상태가 곧 기본 상태). — `GHA:359`

현재 baseline 정의("활성 Scene 의 params 프리셋이 baseline")와 같은 사상이다.

### 갈아엎을 때 건드리지 말 것

> - **Analyzer 모듈** — 수식 분석은 시각화와 독립적으로 가치가 있다
> - **Explorer 관련 코드** — ExplorerOverlay, semantic-roles, 카탈로그 시스템 모두 유지
> - **렌더링 파이프라인** — astToBox, layoutBox, renderBox 는 절대 건드리지 않는다
>
> — `FW:71-76`
