# 화학식 지원 — 현재 범위와 남은 것

`\ce{}` 로 mhchem 표기를 쓴다. 이 문서는 **어디까지 되고 무엇이 왜 안 되는지**를
적는다. 하지 않기로 한 것은 그 근거까지 남긴다 — 다음 사람이 같은 판단을 다시
하느라 시간을 쓰지 않게.

기준일 2026-09-10.

## 되는 것

파싱·조판·왕복·의미 해석이 모두 닫혀 있다.

| | 예 |
|---|---|
| 화합물·계수 | `\ce{2H2 + O2 -> 2H2O}` |
| 전하 | `\ce{SO4^2-}`, `\ce{Ca^2+}` |
| 상태 | `\ce{NaCl (aq)}` |
| 동위원소 | `\ce{^{227}_{90}Th}` |
| 수화물 | `\ce{CuSO4 * 5H2O}` |
| 침전·기체 | `\ce{BaSO4 v}`, `\ce{H2 ^}` |
| 화살표 6종 + 조건 라벨 | `\ce{A <=>[cat][heat] B}` |
| 착이온 | `\ce{[Cu(NH3)4]^2+}` |
| 수식·명령 삽입 | `\ce{$x$ H2O}`, `\ce{A ->[\Delta] B}` |

여기에 붙은 것: 첨자 조판(TeX Rule 18a~18e + 앞첨자), 화학 의미 어휘(전하·원자 수·
질량수·계수·반응 조건…), 원소 118개 이름표, 카탈로그 14건, 웹사이트 노출.

**왕복은 문자 동일이 아니라 정규형 수렴이다.** `\ce{H_2O}` 는 `\ce{H2O}` 가 되고
그 뒤로는 몇 번을 왕복해도 그대로다.

## 하지 않기로 한 것

### 원자단 이름 — 일반 해법이 없다

`Ca(OH)2` 의 `OH` 를 "수산화 이온" 으로 설명하는 것. **괄호가 있으면 가능하고
없으면 불가능하다.**

```
\ce{Ca(OH)2}   text(Ca) · paren[text(O), text(H)] · num(2)   ← (OH) 가 한 노드
\ce{NaOH}      text(Na) · text(O) · text(H)                  ← 가리킬 노드가 없다
```

괄호가 없는 쪽을 하려면 파서가 원자단을 묶어야 하는데 형태만으로는 결정할 수
없다 — `H2O2` 의 `O2` 는 원자단이 아니고 `CH3COOH` 의 `COOH` 는 카복실기다.
화학 지식이 필요하고, 편집으로 임의 조합이 만들어질 수도 있다.

괄호가 있는 경우만 사전을 붙이는 것은 가능하다(지금은 "원자단" 이라고만 나온다).
다만 절반만 되는 기능이라 보류했다.

### 반응식 안 화학종 설명 — 위와 같은 원인

```
\ce{H2O}                 → chem 노드가 카탈로그에 매칭돼 "물"
\ce{2H2 + O2 -> 2H2O}    → "화학종" · "수소" · "산소". H2O 를 가리키는 노드가 없다
```

화학식 하나만 있으면 그 전체가 한 노드라 카탈로그 이름이 뜬다. 반응식 **안의**
`H2O` 는 `scripts` + `text` 로 쪼개져 있어 안 된다. 카탈로그 상세의
`elementMeanings` 를 화학 항목에 채우지 않은 것도 이 때문이다 —
`engine.ts` 의 `findElementKey` 가 노드 하나에서 키를 만드는데 화학종은 구간이다.

## 남은 것

### 편집 경로가 없다 — 지금 화학식은 읽기 전용이다

**이것이 가장 큰 미완이다.**

- `createChem` 을 부르는 곳은 파서뿐이다. `editor.ts` 에는 없다. 즉 화학식은
  LaTeX 를 파싱해야만 생긴다.
- 만들어진 화학식 안에 들어가 고칠 수도 없다. `\ce{H}` 를 놓고 커서를 0~4칸
  옮겨가며 `2` 를 눌러도 전부 `\ce{H}2` 가 된다 — 입력이 화학식 밖으로 나간다.

열려면 두 겹이 필요하다.

1. **삽입 경로** — 제안 목록(`suggestion-engine.ts`)에 화학식 항목을 넣고 빈
   chem 노드를 만든다. `editor.ts` 의 노드 팩토리(editor id 계열)도 필요하다.
2. **chem 스코프의 입력 규칙** — 이쪽이 크다. "`H` 다음 `2` 는 아래첨자",
   "`-` 는 화살표 후보", "첨자 안 `+`/`-` 는 전하" 같은 규칙이 지금은 **파서에만**
   있다. 편집기가 같은 규칙을 알아야 타이핑 중에도 표준처럼 보인다.
   설계 당시엔 "편집으로 생긴 평평한 상태는 재파싱 때 접힌다" 로 정해 뒀는데,
   그러면 입력 중에는 계속 어긋나 보인다.

`cursor-policy.ts` 에 `chem: { content: SUBEXPR }` 가 이미 있고 커서 정책의
자리는 잡혀 있다. 막힌 것은 삽입과 입력 해석이다.

### mhchem 문법의 나머지

설계 때 "코어" 를 택하고 미룬 것들이다. 확장을 대비해 **재진입 가능한
토크나이저**, **첨자를 전하 전용으로 특화하지 않기**, **`-` 다의성 명문화** 세
가지를 지켜 두었으므로 그 위에 얹으면 된다.

| | 현재 동작 |
|---|---|
| 결합 `-` `=` `#` | `unsupported` 경고 + **글자는 남긴다**(조판은 안 한다) |
| `\bond{-}` | 깨진다 — `\ce{C\bond{-}C}` → `\ce{C-}C` |
| `\pu{123 kJ/mol}` | 단위가 수식으로 해석된다 → `123kJ / mol`. `\ce` 안에 넣으면 더 나쁘다 — `\ce{\pu{123 kJ/mol}}` → `\ce{123 kJmol}` 로 슬래시가 사라진다 |
| 산화수 `Fe^{II}` | 왕복은 되지만 mhchem 처럼 로마 숫자로 특별 조판하지는 않는다 |

`\bond` 를 다룰 때 `chem/parser.ts` 의 `case 'command'` 안에 명령 이름별 분기를
넣지 말 것 — C2 가 금지하는 형태다. `latex/commands/` 레지스트리로 가야 한다.

### 조판 검증에 화학 케이스가 없다

`\ce{SO4^2-}` 의 폭 2.500 / 아래첨자 +0.300 / 위첨자 x 1.700 은 표준(KaTeX·MathJax)과
손으로 대조해 확인한 값일 뿐 어느 테스트에도 고정돼 있지 않다. 단위 테스트
(`src/box/ast-to-box.test.ts`)는 상대 관계만 본다.

layout spec 에 넣는 것이 자연스럽지만 **그 스위트는 게이트가 아니라 리포트다** —
`docs/layout-spec-gate.md` 참조. 거기부터 풀어야 의미가 있다.

## 고칠 때 조심할 것

- **화학식 안의 기호는 수학 기호가 아니다.** `+` 는 화학종 구분자이고 위첨자는
  전하다. `walkAST` 가 chem 스코프에서 수학 어휘 수집을 멈추는 이유이고,
  이 한 곳이 뚫리면 도메인·특징·시각화 판정이 한꺼번에 어긋난다.
- **아래첨자와 위첨자를 한 원자에 쌓지 않는다.** `SO4^2-` 의 `2-` 는 O 의 지수가
  아니라 화학종 전체의 전하다. 한 노드에 담으면 조판이 둘을 같은 x 에 세로로
  쌓고(TeX Rule 18e) 아래첨자가 표준보다 내려간다.
- **입력을 버리지 않는다.** 지원하지 않는 표기라도 경고를 내고 글자는 남긴다.
  `O=C=O` 가 `OCO` 가 되면 다른 화학식이다.

  경계 사례가 하나 있다. 화살표를 잘못 치면 성한 글자만 남는다 —
  `\ce{A<=B}` 는 `<` 가 화학 문법에 단독으로 없어 버려지고 `=` 만 남아
  `\ce{A=B}`, 즉 이중 결합처럼 읽힌다. `syntax` 와 `unsupported` 경고가 둘 다
  나오므로 조용한 손실은 아니지만, 오타 복구까지 하려면 화살표 표기를 부분
  일치로 되살리는 별도 설계가 필요하다. 지금은 문자마다 독립으로 판정한다.
