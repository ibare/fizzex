- **영향** — 무엇이 막히는지

## B4. 절댓값이 여는 자리에 오면 뒤 토큰이 중복된다

**증상** — 절댓값이 앞서는 수식에서 직렬화 결과에 여분의 토큰이 붙는다.
AST 의 `sourceRange` 도 입력 길이를 넘는다.

```
\{ |x| \}      → "\{|x|\}||"   (여분 ||, sourceRange 가 +2 초과)
\{ |1 \}       → "\{|1\}|"     (+1)
\{ a, |b| \}   → "\{a,|b|\}||" (+2)
```

내용이 절댓값보다 앞서면 문제가 없다 — `\{ x : |x| < 1 \}` 는 정상이다.

**위치** — `src/latex/latex-parser.ts` 의 `parseExpression` 절댓값 분기(`:138-143` 부근)

**원인** — `|` 를 stopChars 검사보다 **먼저** 절댓값 시작으로 처리하고, 안쪽 파싱에
`['|']` 만 종료 토큰으로 넘긴다. 그래서 닫는 `|` 를 어디로 볼지 정하는 휴리스틱이
바깥 종료 토큰을 알지 못한 채 판단하고, 그 뒤 토큰을 안쪽이 삼킨다.

**영향** — 왕복 문자열에 여분 토큰이 남는다. 직렬화 결과를 다시 읽으면 같은 결과가
나오므로(왕복 자체는 안정) 조용히 번진다.

집합 표기에도 걸린다 — `\{ ... \}` 핸들러는 안쪽 파싱이 선스캔이 찍은 자리에서
멈췄을 때만 집합으로 묶는다. 그래서 `\{ |x| \}` 는 집합이 되지 못하고 중괄호
글리프로 남는다.

**남겨 둔 이유** — `|` 의 여닫음 판정은 본질적으로 모호해서(`|a|b|` 는 두 가지로
읽힌다) 휴리스틱을 손대면 절댓값 전반이 흔들린다. 중괄호 작업과 독립된 문제라
따로 다룬다.
